# Star Lens

Reads what is on the screen (milestone M0.4,
`docs/architecture/m04-apps-lens-storage-design.md` section 5, ADR-0012).
Start it with Meta+Shift+L or from the launcher, select an area, and Star
Lens shows:

- the text in it, recognised by [Tesseract](https://github.com/tesseract-ocr/tesseract)
  (English), on the computer;
- one QR code or barcode, read by KDE's Prison scanner (ZXing), on the
  computer;
- the web links in either.

Buttons copy the text, the code or the image, save the image to
`~/Pictures/Star Lens/`, open a found link or a Google search for the text in
the browser, and "Search with Google Lens". That last one asks first, every
time, because it sends the image to Google: Star Lens copies and saves the
image and opens <https://lens.google.com/> in the browser, where you paste or
upload it. Star Lens itself never uploads anything.

## Keys

| Key | While selecting | With results |
| --- | --- | --- |
| Ctrl+A | select the whole screen | |
| Arrows / Shift+arrows | move / resize the selection | |
| Return | read the selection (all of it if none) | |
| Tab | | move between the buttons |
| Escape | close Star Lens | select again |

## How it works

- The screenshot comes from KWin's `org.kde.KWin.ScreenShot2` interface
  (`CaptureActiveScreen`, a raw image over a pipe) before any window is
  shown. KWin allows it because `org.staros.lens.desktop` lists the interface
  in `X-KDE-DBUS-Restricted-Interfaces` and its `Exec` is the absolute path of
  the running program. There is no permission bypass.
- Copies go through KDE's `KSystemClipboard`. On Wayland a copy is served by
  the program that made it, and Star OS has no clipboard manager, so after a
  copy Star Lens closes its window but keeps running until something else is
  copied.
- Links and searches open with KIO in the default browser (Firefox).

## Build and test

Needs Qt 6.12, KDE Frameworks 6.31 (KIO, GuiAddons, Prison with its scanner)
and ECM; the tests also use Tesseract with English data and a font.

```sh
cmake -B build -S apps/lens -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DBUILD_TESTING=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

The tests run headless and without a session bus, so they never reach KWin:
the recogniser reads text rendered by the test and codes generated by Prison,
the backend works on a capture given by the test, the view uses a test
double, and the real window must report that the screenshot failed. In CI the
`packages` job builds `distro/packages/staros-lens/PKGBUILD`, whose `check()`
runs them; the session test (S17) runs Star Lens in the live session.
